## Architecture

Docker Agent is a thin REST wrapper over the **moby/moby** Docker SDK, written in **Go 1.25 + Fiber v3**, compiled CGO-disabled to a single static binary, and shipped as a multi-stage Alpine image. It's the smallest possible thing that makes a Docker daemon controllable from a script over HTTP without giving an attacker arbitrary code execution.

### Layered structure

```
internal/
  router/     # Fiber app, middleware chain, route registration
  middleware/ # auth, request-id, request logging, recover
  handler/    # parse → validate → call service → return JSON
  service/    # translate API models ↔ Docker SDK types
  model/      # request/response DTOs (the API contract)
  config/     # env loading + validation
```

Each layer talks to the next through an interface, so the Docker client is injected as `DockerClient` rather than a concrete `moby/moby` reference — mockable for tests, swappable in principle, and a clean seam between transport and Docker semantics.

### Request flow

```
Request
  → recover
  → requestid
  → requestLogger
  → [/health bypasses auth]
  → keyauth        (constant-time compare on X-API-Key)
  → rateLimiter    (100 req/min per API key)
  → handler
  → service
  → Docker daemon (Unix socket or DOCKER_HOST)
  ← errdefs-classified JSON error envelope or success payload
```

Rate limiting sits *behind* auth on purpose — unauthenticated callers can't burn through anyone's quota. The limiter is keyed on the API key, not the IP, so it works correctly behind a proxy or load balancer.

### Auth model

A single `X-API-Key` header with three deliberate properties:

1. **Min 32 characters**, validated at startup; the process refuses to boot with a weak key.
2. **`crypto/subtle.ConstantTimeCompare`** for the comparison — no timing side channel for length-extension or character-by-character guessing.
3. **Single failure mode** — invalid or missing key both return `401 { "error": "unauthorized", "message": "missing or invalid API key" }`. No information leak about whether the key existed but expired vs. never existed.

### API surface (intentionally small)

| Endpoint | Purpose |
|---|---|
| `POST   /api/v1/containers` | Create with image, cmd, env, ports, volumes, networks, resource limits, restart policy |
| `GET    /api/v1/containers?all=true` | List running (or all) |
| `GET    /api/v1/containers/:id` | Inspect (full Docker inspect response) |
| `POST   /api/v1/containers/:id/stop` | Stop with timeout + signal (validated against POSIX allowlist) |
| `DELETE /api/v1/containers/:id?force=true&v=true` | Remove, optionally with volumes |
| `GET    /api/v1/containers/:id/logs?follow=false` | Fetch logs, or stream via SSE when `follow=true` |
| `POST   /api/v1/files` | Write files into the host filesystem (mounted at `/host`) with symlink and traversal protection |
| `GET    /health` | Daemon connectivity probe (no auth) |

No `exec`, no `image build`, no network or volume CRUD. The API is container-centric, not arbitrary-process-centric, and that's the security model.

### Input validation

Validation happens **before** the Docker call, so malformed input never reaches the daemon:

- Port ranges clamped to 1–65535
- Signals checked against a hardcoded POSIX allowlist (SIGTERM, SIGKILL, etc.) — unknown signals rejected, not passed through
- File paths must be absolute, `..` rejected, then `filepath.EvalSymlinks` resolves parent dirs to verify the result still lives inside `/host`
- File permissions parsed as octal, capped at `0o7777`
- Restart policies enum-validated (`no`, `always`, `on-failure`, `unless-stopped`)
- Request body capped at 10 MB via Fiber's `BodyLimit`

### Error classification

Docker errors are classified through `containerd/errdefs` type assertions — `IsNotFound` → 404, `IsConflict` → 409, etc. — with a string-match fallback for errors that don't implement the interfaces. Every error returns the same envelope: `{ "error", "message", "status" }`. Callers can rely on HTTP status alone.

### Log streaming

`follow=true` flips the response to **Server-Sent Events** via Fiber v3's `c.SendStreamWriter()`. `WriteTimeout` is intentionally zero on the listener so long-lived streams don't get killed mid-flight. No polling, no websocket complexity, no extra protocol — SSE is the right tool when the channel is one-way.

### Deployment

```
docker run -d \
  -e API_KEY=<32+ char key> \
  -p 3000:3000 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /:/host \
  dockeragent
```

`/var/run/docker.sock` gives the agent the daemon; `/host` gives it the filesystem for the file-write endpoint. Standalone (non-containerized) usage works identically — the binary respects `DOCKER_HOST` so it can target a remote daemon over TCP or SSH.

Graceful shutdown is wired through Fiber's context-aware shutdown with a 10-second drain on SIGINT/SIGTERM, and the Docker client closes cleanly so in-flight log streams aren't ripped out from under their subscribers.

## Design choices worth calling out

- **Single binary, no plugins** — the API is intentionally finite. Adding `exec` or arbitrary shell would unlock the entire host; refusing to add them is the security story.
- **errdefs-driven status codes** — Docker errors are heterogeneous; classifying them upstream means handlers stay free of `if strings.Contains` chains.
- **SSE over WebSocket for logs** — one-way, browser-native, debuggable with `curl`. No protocol upgrade.
- **Two layers of path-traversal defense** — rejecting `..` *and* resolving symlinks catches the case where a parent directory doesn't exist yet but a symlink to escape `/host` does.
